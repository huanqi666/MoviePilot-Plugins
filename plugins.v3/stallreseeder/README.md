# 卡种换源（StallReseeder）

qBittorrent 里一个种子卡在 0%（死种）时，MoviePilot 既不会判定它失败，也不会换源：

- 下载阶段卡住，对 MP 来说既不算成功也不算失败，永远不会写进下载失败台账；
- 订阅搜索会把"已推送"的集数记为已处理，缺集数归零，于是没有动机再选；
- 停滞清理插件只会删任务，删完订阅仍然缺集，下一次收集又会选中同一个死种。

本插件把闭环串起来。

## 处理流程

1. **判定停滞**：只看一个字节都没下载的 0% 任务（默认），正在慢速下载的任务绝不处理；
2. **反查身份**：用下载历史按 hash 拿到媒体身份、季集、来源站点；
3. **定位资源**：回到原站点搜索同一个发布，拿到资源页面；
4. **写冷却**：用 MP 自己的算法算出与该资源一致的冷却指纹，写入原生 `downloadfailure` 台账，订阅搜索就会主动跳过这颗死种，去挑下一个资源；
5. **触发重搜**：定向触发该订阅的一次搜索，筛选与下载仍由 MP 自己完成，不复制规则引擎。

找不到资源页面时自动退回"只删 + 重搜"，绝不乱写指纹。

## 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| 执行周期 | `*/15 * * * *` | cron 表达式 |
| 下载器 | qBittorrent | 要监控的下载器 |
| 停滞判定时长 | 30 分钟 | 0% 状态持续多久算死种 |
| 速度阈值 | 10 KB/s | 低于该速度视为无速度 |
| 仅处理 0% 任务 | 开 | 关掉后有进度的任务也会被判定，不建议 |
| 新任务保护期 | 30 分钟 | 刚添加的任务不参与判定 |
| 单轮最多处理 | 2 | 上限保护，避免一次性换掉太多任务 |
| 冷却时长 | 24 小时 | 写入失败台账后的跳过时间 |
| 换源后重搜 | 开 | 定向触发该订阅搜索 |
| 豁免标签 | `刷流` | 带这些标签的任务永不处理 |
| 演练模式 | 开 | 只记录不动作，建议先跑一轮 |
