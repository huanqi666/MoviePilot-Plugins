# 洗版残留清理（VersionCleaner）

洗版（best version）把片子换成更好的版本后，媒体库里只会保留一份，但**下载目录里那些被淘汰的数据文件不会自己消失**。

原因在整理方式：MoviePilot 用硬链接入库，库内文件和下载目录文件指向同一个 inode。洗版覆盖后，库内那条链接被换成新文件，旧文件的链接数从 2 变成 1 —— 数据还在，只是没人用了，qB 里那个旧种子还在继续做种。一部 86GB 的 Remux 加上一份 WEB-DL，就是一百多 GB 的白占。

## 判定逻辑

插件读 MoviePilot 的整理历史（`/config/user.db` 的 `transferhistory`，只取成功记录），拿到每条「下载路径 → 库内路径」，然后逐条核验：

1. 下载文件还在、体积达标、已过保护期；
2. **硬链接数 = 1** —— 库里已经不再引用这份数据；
3. 再看库内目标：
   - 目标还在且 inode 相同 → 仍在使用，跳过（复制模式下用「大小相同 + 修改时间接近」兜底）；
   - 目标还在但已换成别的文件 → 判定为旧版；
   - 目标已不在：
     - 剧集：同目录已有**同季同集**的其它视频 → 判定为旧版；
     - 电影：该片目录里已有别的视频 → 判定为旧版（洗版换封装格式时库内文件名会从 `- 2160p.iso` 变成 `- 2160p.mkv`，旧目标自然不存在）。

用整理历史而不是靠剧名文本比对，是因为库内会重命名成中文（`The Odyssey` → `奥德赛 (2026)`），英文发布名对不上；inode 校验则保证不会误伤正在用的那份。

## 删除之后

- 文件删除后，按记录里的 `download_hash` 判断该任务的文件是否已全部不存在，是则把任务从下载器移除（只删任务，不再删文件）；
- 顺着被清空的目录向上删空目录，止于下载根目录。

## 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 关 | 总开关 |
| 发送通知 | 开 | 有删除或异常时发通知 |
| 立即运行一次 | 关 | 保存后马上跑一轮 |
| 演练模式 | 关 | 只记日志不删文件，建议先跑一轮 |
| 执行周期 | `0 5 * * *` | 每天凌晨 5 点 |
| 保护期（小时） | 24 | 刚下载/刚整理的文件不处理，防止误删正在洗版的目标 |
| 最小文件（MB） | 100 | 小于该体积不处理，避开样片、字幕组小文件 |
| 单轮最多删除 | 200 | 上限保护 |
| 移除空任务 | 开 | 文件删完顺带把任务从下载器移掉 |
| 清理空目录 | 开 | 删完的空目录向上清理 |
| 下载目录 | 空 | 留空自动用 `/media/downloads` |
| 媒体库目录 | 空 | 留空自动扫描 `/media`（会跳过下载目录） |

## 安全边界

- 只处理下载目录，且只处理**硬链接数 = 1** 的文件；库里正在用的文件链接数至少是 2，不会被选中；
- 必须有整理历史记录，且库内能确认已换成新版本才动手，找不到就跳过；
- 保护期内的文件一律跳过，避免把刚下载好、还没整理完的新版本当成旧版删掉；
- 媒体库文件是另一个硬链接，删下载目录那份不影响播放。

## 与洗版设置的关系

MoviePilot 的整理覆盖模式（设置 → 目录 → 覆盖模式）建议用 `latest`：命中同名目标时覆盖，并在目标文件不存在时清理同目录的其它版本。但覆盖模式只认「同名」，换封装格式（ISO → MKV）会产生不同文件名，库里会一度并存两份；它更管不到下载目录里那半边。本插件补的就是这两处。
