# 洗版残留清理（VersionCleaner）

洗版（best version）把某一集换成更好的版本后，媒体库里只会保留一份，但**下载目录里那一条旧版本的数据文件不会自己消失**。

原因在整理方式：MoviePilot 用硬链接入库，库内文件和下载目录文件指向同一个 inode。洗版覆盖后，库内那条链接被换成新文件，旧文件的链接数从 2 变成 1 —— 数据还在，只是没人用了，qB 里那个旧种子还在继续做种。一集 5GB 的话，几十集就是几百 GB。

插件做的事很简单：

1. 扫描媒体库，建立「季 + 集 → 库内文件」索引，同时记下每部剧的名称关键词；
2. 扫描下载目录，找**硬链接数为 1**、体积达标、且已过保护期的视频文件；
3. 如果同一季同一集在库里已经有别的文件、剧名也对得上，就认定它是被洗版淘汰的旧版本，删除。

只删下载目录里那份，媒体库文件是另一个硬链接，完全不受影响。

## 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 关 | 总开关 |
| 发送通知 | 关 | 有删除或异常时发通知 |
| 立即运行一次 | 关 | 保存后马上跑一轮 |
| 演练模式 | 关 | 只记日志不删文件，建议先跑一轮 |
| 执行周期 | `0 5 * * *` | 每天凌晨 5 点 |
| 保护期（小时） | 24 | 刚下载/刚整理的文件不处理，防止误删正在洗版的目标 |
| 最小文件（MB） | 100 | 小于该体积不处理，避开样片、字幕组小文件 |
| 单轮最多删除 | 200 | 上限保护 |
| 下载目录 | 空 | 留空自动用 `/media/downloads` |
| 媒体库目录 | 空 | 留空自动扫描 `/media`（会跳过下载目录） |

## 安全边界

- 只处理下载目录，且只处理**硬链接数 = 1** 的文件；库里正在用的文件链接数至少是 2，不会被选中；
- 必须有「同季同集 + 剧名匹配」的库内文件才动手，找不到就跳过；
- 保护期内的文件一律跳过，避免把刚下载好、还没整理的新版本当成旧版删掉；
- 删除后残缺的下载任务不会一直挂着：MoviePilot 的下载器助手会按「文件丢失」规则清理任务。

## 与洗版设置的关系

MoviePilot 的整理覆盖模式（设置 → 目录 → 覆盖模式）建议用 `latest`：命中同名目标时覆盖，并在目标文件不存在时清理同目录的其它版本。本插件补的是它管不到的另一半——下载目录里的旧版本数据。
