# 站点自动签到（AutoSignIn）

MoviePilot 插件：自动模拟登录并签到 PT 站点。

本目录是**上游 thsrite/AutoSignIn 3.0.10 的补丁版**，其余逻辑与上游一致。

## 与上游的差异

### 1. 签到 / 登录请求加超时重试

| 请求 | 上游 | 本版 |
|---|---|---|
| 签到（`__signin_base`） | 失败直接判定"签到失败，无法打开网站" | 最多 3 次，首次用原超时，重试用 20s，间隔 5s |
| 模拟登录（`__login_base`） | 失败直接返回失败 | 最多 2 次，同上 |

起因：整点定时任务高峰时，个别站点会偶发 TLS 握手挂起，`RequestUtils.get_res` 返回 `None`。上游此时直接判失败，随后只做模拟登录、不重试签到，当天记成"登录成功，签到未确认"且不再重试。

### 2. 宿主无 `test_site` 能力时回退网页签到（3.0.10.2）

上游 3.0.10 对没有专用站点模块的站点（如织梦、咖啡、NovaHD）改走宿主的
`chain.run_module("test_site")` 做连接检测。但这个方法在 **MP v3.2.5 及更早版本里并不存在**，
分发器按"空结果"返回 `None`，上游代码把 `None` 直接判成
`签到失败，站点模块未返回连接检测结果`，而且**不再回退**网页签到——结果是三个站点全部失败，
且整轮只花 140ms，一个 HTTP 请求都没发。

本版把 `None` 与"明确不支持该站点"同等处理，交回原有的 cookie + `attendance.php` 网页签到。
等宿主补齐 `test_site` 后，这段逻辑会自动走回 API 检测，无需再改。

## 版本

- `3.0.10.2` — 上游 3.0.10 + 请求重试 + `test_site` 缺失回退
- `3.0.10.1` — 上游 3.0.10 + 请求重试（在 MP v3.2.x 上签到全部失败，勿用）
- `3.0.6.1` — 上游 3.0.6 + 请求重试（旧基线，已废弃）

上游发新版本后需要把新代码合并进来并递增版本号；只想跟随上游、不需要这些补丁时，直接装官方市场的 AutoSignIn
（前提是宿主版本已经提供 `test_site`）。
