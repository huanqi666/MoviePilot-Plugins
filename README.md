# MoviePilot Plugins

自用的 MoviePilot 插件合集：解决死种占用下载队列、0% 死种不换源、订阅里"已下载"记录与媒体库对不上、运行垃圾堆积，以及签到高峰的请求超时。

## 插件列表

| 插件 | 作用 | 定时 |
|---|---|---|
| [停滞下载清理](plugins.v3/stallcleaner) | 未完成任务连续无进度且速度低于阈值时，自动暂停或删除 | 默认每小时 |
| [系统垃圾清理](plugins.v3/housekeeping) | 清理图片缓存、临时文件、旧日志、调试残留 | 默认每周一 04:00 |
| [订阅缺集自愈](plugins.v3/subscribehealer) | 订阅搜索前核对媒体库与已下载记录，剔除失效声明并补搜缺集 | 默认每日 04:00 + 每次订阅搜索前 |
| [卡种换源](plugins.v3/stallreseeder) | 0% 死种自动删任务、写入 MP 冷却台账，并触发订阅重搜换源 | 默认每 15 分钟 |
| [站点自动签到](plugins.v3/autosignin) | 模拟登录并签到 PT 站点（上游 3.0.10 + 请求重试 + 宿主能力缺失回退） | 按站点配置 |

除签到外，其余四个都带**详情面板**：打开插件详情页可以看到运行状态、上次执行结果、当前正在跟踪的对象和执行历史，不是点了按钮就"黑箱"。

## 安装

MoviePilot → 设置 → 插件市场 → 添加插件仓库：

```
https://github.com/huanqi666/MoviePilot-Plugins
```

保存后刷新插件列表，搜索「停滞下载清理」「系统垃圾清理」「订阅缺集自愈」「卡种换源」或「站点自动签到」安装即可。

仓库同时提供两套索引，按宿主版本自动选择：`package.v3.json` + `plugins.v3/`（MoviePilot 3.x）、`package.v2.json` + `plugins.v2/`（2.x）。每个插件都有对应的 GitHub Release（标签 `<插件ID>_v<版本>`，资产 `<插件id>_v<版本>.zip`），市场"切换来源"与按版本安装都依赖它。

也可以手动放置：把 `plugins.v3/<插件目录>` 整个复制到 MoviePilot 的插件目录（容器内 `/app/app/plugins/`），重启后启用。

## 停滞下载清理

qBittorrent 原生只按**分享率**和**做种时长**删种，两个条件都只对**已下载完成**的种子生效。下载阶段的死种（tracker 通、但 peer 是假的）会永远停在 `stalledDL`，占着队列名额不动。

这个插件补的就是这一段：扫描未完成任务，若**进度连续 N 分钟没有变化**且**当前速度低于阈值**，就按配置处置。

配置项：

| 配置 | 默认 | 说明 |
|---|---|---|
| 执行周期 | `0 */1 * * *` | cron 表达式 |
| 下载器 | 无 | 选择要监控的下载器，目前支持 qBittorrent |
| 停滞判定时长 | 60 分钟 | 进度连续无变化多久算停滞 |
| 速度阈值 | 10 KB/s | 低于该速度视为"无速度" |
| 新任务保护期 | 30 分钟 | 刚添加的任务不参与判定 |
| 处置动作 | 删除任务（保留文件） | 可选：仅暂停 / 删任务 / 删任务及文件 |
| 豁免标签 | `刷流` | 带这些标签的任务永不处理，避免和刷流插件冲突 |
| 演练模式 | 关 | 只记录名单，不真的处置 |

判定逻辑有几个刻意保留的安全边界：只有**进度不变 + 速度低**同时满足才开始计时；中途恢复速度或进度前进，计时立即清零；新任务有保护期；带豁免标签直接跳过。

## 系统垃圾清理

只清理 `/config` 下**可以安全重建**的数据，删除后不会影响运行：

| 清理项 | 路径 | 说明 |
|---|---|---|
| 图片/接口缓存 | `config/cache` | 超过阈值才清，避免海报被反复重拉 |
| 运行临时文件 | `config/temp` | 运行时产生的中间文件 |
| 旧日志 | `config/logs` | 轮转日志 + 超过保留天数的日志，**当前 `moviepilot.log` 永不删除** |
| 调试残留 | `config/tmp_*.html`、`tmp_*.json` | 调试遗留的临时文件 |

明确不碰：`user.db`、`app.env`、`cookies`、`plugins`、媒体库目录、下载目录。

配置项：执行周期、缓存阈值（MB，0 表示每次都清）、日志保留天数、四项开关、演练模式、通知开关。

> 清理 `config/cache` 之后，MoviePilot 首次启动可能会重新同步插件市场索引，表现为插件列表暂时不全。重启一次容器即可恢复，不影响插件配置。

## 订阅缺集自愈

MoviePilot 在**提交下载的那一刻**就把集号写进订阅的 `note` 和 `episode_priority`，之后种子被删、下载失败、文件被清理，这些记录都不会回滚。

后果分两种：

- 普通订阅：这几集被当成"已下载"，永远不再搜索；
- 开启洗版的订阅（`best_version`）：更糟——它们被当成**升级候选**，只有当新资源优先级高于原记录时才接受，而站点上同级资源永远满足不了，于是**永久发现不了**。

典型触发场景：4K 冷种下到 10% 没有速度，被清理插件或人工删掉，记录却留了下来。

这个插件补的就是这一段。以**媒体库实际文件**为唯一事实，核对订阅里"已下载"的声明：

| 判定 | 处理 |
|---|---|
| 订阅声明已下载，媒体库确有对应文件 | 不动 |
| 声明已下载，媒体库无文件，且种子仍在下载器 | 视为在途，跳过 |
| 声明已下载，媒体库无文件，但下载记录指向的文件还在磁盘 | 视为在途，跳过 |
| 声明已下载，媒体库无文件，记录在保护期内 | 跳过，避免抢在下完/整理前重下 |
| 以上都不成立 | 认定记录失效，剔除声明并触发补搜 |

**时机是关键**：钩子挂在订阅搜索入口上，每轮搜索开始前先对账，清完当轮就补，不用等下一次巡检。另外保留一个每日兜底巡检，处理长期不触发搜索的订阅。

集号识别用 MoviePilot 自己的 `MetaVideo`，支持 `SxxExx`、`第x集`、绝对集号等常见命名；只处理**电视剧**订阅。

配置项：

| 配置 | 默认 | 说明 |
|---|---|---|
| 每次订阅搜索前先核对 | 开 | 推荐开启，这是主要生效路径 |
| 兜底巡检周期 | `0 4 * * *` | 每日巡检，处理不常搜索的订阅 |
| 兜底巡检时自动补搜 | 开 | 巡检清理后是否立即触发该订阅搜索 |
| 记录保护期 | 120 分钟 | 新于此值的记录不判定 |
| 单轮最多清理集数 | 200 | 上限保护，防止误判时一次改太多 |
| 有效文件大小下限 | 10 MB | 小于该值不算有效文件（样片、预告） |
| 媒体库扫描缓存 | 600 秒 | 搜索前核对会频繁扫库，用缓存降低 IO |
| 媒体库目录 | 留空 | 留空自动扫 `/media` 下各分类 |
| 演练模式 | 开 | 只记录不写库，建议先看一轮 |

判定上刻意保守：

- 媒体库该季**有文件但片名和订阅名对不上**时，跳过不判定，避免把命名差异当成缺集；
- 清理前会同时核对下载器任务、下载记录路径、记录时间三项，任一成立即视为在途；
- 同一轮有集数上限，且只在确认失效时才写库。

还有一个容易忽略的门槛：洗版订阅如果把 `note` / `episode_priority` 清空，MoviePilot 会用 `current_priority` 给整季回填基线优先级，日志表现为"正在洗版，优先级未达到当前模式的升级条件"，补搜依然下不下来。插件在整批记录被清空时会同步把 `current_priority` 归零。

## 卡种换源

qBittorrent 里一个种子卡在 0%（死种）时，MoviePilot 既不会判定它失败，也不会换源：下载阶段卡住既不算成功也不算失败，永远不会写进 `downloadfailure` 台账；订阅搜索还会把"已推送"的集数记成已处理，缺集数归零，于是没有动机再选。停滞清理插件删掉任务之后，订阅仍然缺集，下一轮又会选中同一颗死种。

这个插件把闭环串起来：

1. **判定停滞**：只看一个字节都没下载的 0% 任务（默认），正在慢速下载的任务绝不处理；
2. **反查身份**：用下载历史按 hash 拿到媒体身份、季集、来源站点；
3. **定位资源**：回到原站点搜索同一个发布，拿到资源页面；
4. **写冷却**：用 MoviePilot 自己的算法算出与该资源一致的冷却指纹，写进原生 `downloadfailure` 台账，订阅搜索就会跳过这颗死种；
5. **触发重搜**：定向触发该订阅的一次搜索，筛选与下载仍由 MoviePilot 完成，不复制规则引擎。

找不到资源页面时自动退回"只删 + 重搜"，绝不乱写指纹。

配置项：执行周期、下载器、停滞判定时长（30 分钟）、速度阈值（10 KB/s）、仅处理 0% 任务、新任务保护期（30 分钟）、单轮最多换源（2 个）、死种冷却时长（24 小时）、删除后触发重搜、豁免标签（`刷流`）、演练模式。

## 站点自动签到

自动模拟登录并签到正在使用的 PT 站点，`sites/` 下内置 20+ 站点实现。

本目录是**上游 thsrite/AutoSignIn 3.0.10 的补丁版**，改了两处：

**一、签到请求失败重试**：签到请求重试 3 次、模拟登录请求重试 2 次（首次用原超时，重试用 20s，间隔 5s）。起因是整点定时任务高峰时，个别站点会偶发 TLS 握手挂起，`RequestUtils.get_res` 返回 `None`。上游此时直接判失败，随后只做模拟登录、不重试签到，当天记成"登录成功，签到未确认"且不再重试。现在偶发挂起会被重试兜住。

**二、宿主无 `test_site` 能力时回退网页签到**：上游 3.0.10 对没有专用站点模块的站点（织梦、咖啡、NovaHD 这类），改走宿主的 `chain.run_module("test_site")` 做连接检测。这个方法在 MP v3.2.5 及更早版本里并不存在，分发器按"空结果"返回 `None`，上游把 `None` 直接判成「签到失败，站点模块未返回连接检测结果」，并且不再回退网页签到——三个站点会全部失败，整轮仅耗时 140ms，一个 HTTP 请求都没发出去。本版把 `None` 与"明确不支持该站点"同等处理，交回原有的 cookie + `attendance.php` 网页签到；宿主补齐 `test_site` 后会自动走回 API 检测。

上游发新版本后需要把新代码合并进来并递增版本号（当前 `3.0.10.2`）；只想跟随上游、不需要这些补丁时，直接装官方市场的 AutoSignIn 即可（前提是宿主版本已提供 `test_site`）。

## 详情面板

- **停滞下载清理**：运行状态与周期、处置方式、判定阈值、上次命中数；上次执行的扫描/未完成/豁免/保护期/跟踪统计；上次命中明细（任务、停滞时长、速度、进度、处置结果）；**当前无进度任务**（谁在计时、还有多久到阈值）；最近 12 次执行历史。
- **系统垃圾清理**：运行状态与周期、执行模式、缓存阈值、上次释放空间；上次执行的文件数与占用变化；**当前占用实时统计**（缓存/临时/日志的占用与文件数）；最近 12 次执行历史。
- **订阅缺集自愈**：运行状态与"搜索前核对是否挂载"、模式（演练/正式）；上次扫描订阅数、上次清理集数、修复订阅数、跳过集数；**上次清理明细**（订阅、季、清理集数、剩余缺集、判定原因）。
- **卡种换源**：运行状态与周期、模式（演练/正式）、停滞阈值、上次换源数；上次执行的扫描/未完成/豁免/保护期/跟踪统计；**当前跟踪中的 0% 任务**（已停滞时长、还差多久到阈值）；最近执行历史。

执行记录保存在插件数据里（最近 30 次），重启不丢。

## 说明

- 插件均只依赖 MoviePilot 自带的 `app.sdk`，不引入额外第三方库。
- 处置动作、清理范围都可先用**演练模式**跑一轮确认，再切正式执行。
- 代码按"本地自用"标准编写，未经大规模环境验证；删除类操作请务必先看演练结果。
- 站点自动签到是上游 [thsrite](https://github.com/thsrite) 的补丁 fork，感谢原作者。
