# MoviePilot Plugins

两个自用的 MoviePilot 插件：一个解决死种占用下载队列，一个定时清理运行产生的垃圾数据。

## 插件列表

| 插件 | 作用 | 定时 |
|---|---|---|
| [停滞下载清理](plugins.v2/stallcleaner) | 未完成任务连续无进度且速度低于阈值时，自动暂停或删除 | 默认每小时 |
| [系统垃圾清理](plugins.v2/housekeeping) | 清理图片缓存、临时文件、旧日志、调试残留 | 默认每周一 04:00 |

两个插件都带**详情面板**：打开插件详情页可以看到运行状态、上次执行结果、当前正在跟踪的对象和执行历史，不是点了按钮就"黑箱"。

## 安装

MoviePilot → 设置 → 插件市场 → 添加插件仓库：

```
https://github.com/huanqi666/MoviePilot-Plugins
```

保存后刷新插件列表，搜索「停滞下载清理」或「系统垃圾清理」安装即可。

也可以手动放置：把 `plugins.v2/<插件目录>` 整个复制到 MoviePilot 的插件目录（容器内 `/app/app/plugins/`），重启后启用。

## 停滞下载清理

qBittorrent 原生只按**分享率**和**做种时长**删种，两个条件都只对**已下载完成**的种子生效。下载阶段的死种（tracker 通、但 peer 是假的）会永远停在 `stalledDL`，占着队列名额不动。

这个插件补的就是这一段：扫描未完成任务，若**进度连续 N 分钟没有变化**且**当前速度低于阈值**，就按配置处置。

配置项：

| 配置 | 默认 | 说明 |
|---|---|---|
| 执行周期 | `0 */1 * * *` | cron 表达式 |
| 下载器 | 无 | 选择要监控的下载器，目前支持 qBittorrent |
| 停滞判定时长 | 60 分钟 | 进度连续无变化多久算停滞 |
| 速度阈值 | 10 KB/s | 低于该速度视为"无速度" |
| 新任务保护期 | 30 分钟 | 刚添加的任务不参与判定 |
| 处置动作 | 删除任务（保留文件） | 可选：仅暂停 / 删任务 / 删任务及文件 |
| 豁免标签 | `刷流` | 带这些标签的任务永不处理，避免和刷流插件冲突 |
| 演练模式 | 关 | 只记录名单，不真的处置 |

判定逻辑有几个刻意保留的安全边界：只有**进度不变 + 速度低**同时满足才开始计时；中途恢复速度或进度前进，计时立即清零；新任务有保护期；带豁免标签直接跳过。

## 系统垃圾清理

只清理 `/config` 下**可以安全重建**的数据，删除后不会影响运行：

| 清理项 | 路径 | 说明 |
|---|---|---|
| 图片/接口缓存 | `config/cache` | 超过阈值才清，避免海报被反复重拉 |
| 运行临时文件 | `config/temp` | 运行时产生的中间文件 |
| 旧日志 | `config/logs` | 轮转日志 + 超过保留天数的日志，**当前 `moviepilot.log` 永不删除** |
| 调试残留 | `config/tmp_*.html`、`tmp_*.json` | 调试遗留的临时文件 |

明确不碰：`user.db`、`app.env`、`cookies`、`plugins`、媒体库目录、下载目录。

配置项：执行周期、缓存阈值（MB，0 表示每次都清）、日志保留天数、四项开关、演练模式、通知开关。

> 清理 `config/cache` 之后，MoviePilot 首次启动可能会重新同步插件市场索引，表现为插件列表暂时不全。重启一次容器即可恢复，不影响插件配置。

## 详情面板

- **停滞下载清理**：运行状态与周期、处置方式、判定阈值、上次命中数；上次执行的扫描/未完成/豁免/保护期/跟踪统计；上次命中明细（任务、停滞时长、速度、进度、处置结果）；**当前无进度任务**（谁在计时、还有多久到阈值）；最近 12 次执行历史。
- **系统垃圾清理**：运行状态与周期、执行模式、缓存阈值、上次释放空间；上次执行的文件数与占用变化；**当前占用实时统计**（缓存/临时/日志的占用与文件数）；最近 12 次执行历史。

执行记录保存在插件数据里（最近 30 次），重启不丢。

## 说明

- 两个插件均只依赖 MoviePilot 自带的 `app.sdk`，不引入额外第三方库。
- 处置动作、清理范围都可先用**演练模式**跑一轮确认，再切正式执行。
- 代码按"本地自用"标准编写，未经大规模环境验证；删除类操作请务必先看演练结果。
